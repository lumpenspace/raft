# RAFT, three years on

raft was written in 2023 around gpt-3.5 finetuning: a 4k context, no
reasoning phase, memories smuggled into the prompt as a system note, and
OpenAI as the only place to embed, summarise or train. The method — teach a
model how a specific person combines what they wrote before with what is in
front of them now — has aged well. The mechanics had not. This page records
what changed and how 2.8 adapts, so the choices are legible rather than
folklore.

## What changed

**Models think before they answer.** Every model worth finetuning today has
an explicit reasoning phase (`<think>…</think>` in the Qwen3 line, and
equivalents elsewhere). A persona's "memories" are not context handed to it
by a harness; they are what the persona recalls while thinking.

**Context is not scarce.** The 4096-token training window was the binding
constraint of 2023 — hence the packing logic that squeezes as many earlier
exchanges as possible into each example. Today's models train on 32k–256k
tokens; the constraint is no longer real, but the shape of the data still
matters (see below).

**The whole pipeline runs on one desk.** A 27B-class model finetunes on a
Mac with enough unified memory (opbdh's local execution, `--target mps`),
embeddings and summaries come from a local server, and no API key is needed
end to end. Rate-limit sleeps and hard-coded model ids became liabilities.

**Real conversations come with dates.** Tweet threads, forum threads and
Bluesky replies are dated to the second. That makes it possible to be
strict about causality: nothing the persona recalls while replying may have
been written *after* that reply.

## How 2.8 adapts

### Recall lives in the thinking phase

With `--thinking` (or the prep phase's question), each training reply is:

```
<think>
Recalling what I have written before:
from 2024-11-23: I've argued that …
from 2025-01-15: …

<reasoning from that recall, and the question, to the reply>
</think>

<the reply the target actually gave>
```

The recall is the retrieval output raft always produced — chunks of earlier
writing and earlier exchanges, restated in the first person by the
summariser. The reasoning is new: written after the fact from the real
reply, so it teaches how the target moves from memory to answer and never
invents a position. The model is trained on the whole reply (recall,
reasoning, answer). In the older non-thinking format the recall stays a
system note between question and reply, for models without a thinking phase
and for the OpenAI finetuning API.

### One conversation, one date

A transcript is now one conversation — a thread branch, a reply chain, an
interview — with its own date and setting. The system prompt states who the
persona is, the date, and the setting ("a LessWrong comment thread under
the post …"; "a reply thread on X"; "an interview"). Retrieval for that
conversation is filtered to documents dated strictly before it.

### Conversations are memories too

Every exchange the pipeline processes is remembered — question, answer,
date, participants — in the same store as the writing, so a later
conversation can recall an earlier one ("I've said before that …"). The
date filter applies to these like to any document; benchmark conversations
and live chat are never remembered, so they cannot leak into training.

### Limits from the OpenAI era are knobs

| 2023 | 2.8 |
| --- | --- |
| 4096-token examples | 8192, `RAFT_MAX_EXAMPLE_TOKENS` |
| 3 s sleep per exchange, 2 s per file | `RAFT_PACE`, default 0 |
| `gpt-4` summariser, `text-embedding-ada-002` | `RAFT_LLM_MODEL`, `RAFT_EMBEDDING_MODEL`, any OpenAI-compatible `OPENAI_BASE_URL` |
| 40 exchanges batched per transcript | one conversation per transcript |
| "retrieve_memories will be called automatically" | a system prompt that describes the setting and how recall works |

### What did not change

The retrieval-then-summarise step, the usefulness check that drops
irrelevant memories, the earlier-writings filter, and the benchmark
transcripts. The persona is still trained on its own replies only
(completion-only loss in the opbdh runner).

## Running it against a thinking model

```bash
raft ft:gen --thinking            # reasoning traces + <think> formatting
raft ft:run --model Qwen/Qwen3.8-27B --target mps --epochs 1
```

Qwen3's chat templates render an assistant message containing
`<think>…</think>` as reasoning plus content, and prior turns lose their
thinking, exactly as at inference — so the training file needs nothing
model-specific beyond the block itself. Use the `Instruct` variants of a
line with no thinking phase (Qwen3-*-Instruct-2507) without `--thinking`.
